# 磁力小牛产品规划
> 核心命题：**从「工具辅助」到「智能体闭环」——让客户用自然语言"许愿"，Agent自动理解、规划、执行、反馈**
> 
> 这个doc为啥前摇这么长——想看清楚竞对都咋做的、做对了啥做错了啥，我们接下来要做正确的事

## PART 1：立项背景

### 一、总结：竞对对我们的启发

- **全球广告平台已从「工具辅助」跑到「智能体闭环」，我们的单点偏弱**——AI 创编形式领先但覆盖效果还在验证、诊断／数据还在单点突破中，客服已有 AI 版本；**且模块间缺少串联、无统一编排、无长期记忆，所以是「有能力、不成链路」。（Phase 2 弱）**
- **我们的链路断在四处： 诊断→调优（有结论无动作）、数据→诊断/创编（有洞察无策略）、问答→诊断／数据（规则而非推理、现在是固定意向词识别）、执行→反馈（操作与效果断链，调完不知有没有用）**

   。
- **行业最大的矛盾：** 平台越推自动化，客户越只能用结果反推动机——效果好归自己运气、效果差归平台自利，这在信息不对称下完全理性。千川的 review 已经证明：工程问题补到位、**"客户敢用"不解决，结果依然是"能力有了但没人敢用"。** 
- 所以我们的机会是**：以磁力小牛为统一 AI Portal，建「投放总 Agent → 业务 Agent 协同」编排中枢，打通意图理解→任务拆解→多Agent执行→效果反馈→记忆沉淀**。**并把最敏感的调价做成可协商**

   。

> AI投放产品分层与演进路径：**AI投放 = 准确理解客户意图 × 可调用可插拔工具 × 半自动/全自动闭环体系。**Phase 1 工具辅助-系统提供基础工具，无AI；Phase 2 单点智能-AI可生成数据/参考，仍需人工操作；Phase 3 基本智能-AI参与大部分环节，完成分模块任务；Phase 4 AI闭环：端到端闭环，人工仅表达诉求+授权

### 三、竞品核心动态

#### 海外三家：核心变化一览

- 海外主要竞对表面都讲"AI投放"，但要分三层看：**产品层 Meta/Google 是把全托管做到极致**（Advantage+ 已成默认投放方式、AI Max 9月起强制迁移），这层跟 UAX、全站推广同代，**我们不落后**；**底层模型它们确实在换代**（Meta 的 Generative Recommender 是生成式推荐架构，转化+15.7%，快手"生成式推荐大模型带动营销收入+5%"是同一件事）这层要跟；**但 Agent 层它们是落后的，连对话式投放入口都没有。**

#### 国内三家：核心竞争力

**一句话看竞品:三家各自锁死了一样东西 —— 腾讯锁入口、阿里锁生态、千川锁账权。**

**腾讯 AIM+/AdBuddy 的核心竞争力是「入口」**:授权即生成常驻"AI分身",把投放操作从广告后台迁进企微/QQ/微信,三步表达诉求即可执行,并且每次动手前先弹出待确认卡片(项目名/预算/定向/出价/版位)、客户点确认才生效 —— **"先给清单再执行"这套白盒范式,腾讯已经做成公开可注册的产品。**

**阿里万相台的核心竞争力是「生态 + 记忆」**:2026年3月推出电商行业首个集成 AI Agent 的"AI生意管家",用**1个AI店长统筹 + 6个AI员工分工**的架构覆盖经营全场景,更关键的是**支持第三方及自研商家 Skills 无缝挂载**、并基于商家个性化特征训练出**长期"商家记忆"**。前者意味着它在建平台和标准而非造功能,后者意味着越用越难迁移。规模上已跑到 **500万商家、效率+1.5倍、覆盖90%经营场景** —— **这是全球范围内 Agent 化唯一被规模验证过的案例,连 Amazon 都只报了 CPM-18%/CPA-16%、覆盖率未披露。**

**千川·乘方的核心竞争力是「账权」**:它把**广告花费与达人佣金统一核算**,直接回答"钱该怎么花"这个终极问题 —— 这不是 AI 能力,是只有电商闭环在手才做得到的能力。但它的 review 也自陈短板:Agent 底层架构未统一、营销 Skill 效果不及预期、claw 工具覆盖不足,**乘方消耗渗透 30.47% 且环比 -2.4pp、正向率 74% 低于全域 81%**,自评"还远远没有成为商家的主投放选择"。

## PART 2：产品矩阵全景

### 一、Agent化架构

- **整体来看，这些 AI 产品计划 Q3 达成“单点能力可用、关键链路跑通”**

   ：
    - 创编 Agent 打开场景漏斗并补齐意图识别、效果保障和评测数据；
    - 诊断 Agent 完成从规则判断到 LLM 推理诊断的架构改造并达到对客灰度标准；
    - 数据 Agent 跑通“看数→发现异常→诊断归因”
    - 磁力小牛提升问答质量、问题解决率和场景渗透；同时建成多模态、多轮对话、记忆、评估平台和知识管理等共用底座。
- **Q4 达成“多 Agent 协同、全链路闭环”**：**小牛升级为统一入口和编排中枢，串联创编、投放、数据洞察、诊断、调价、效果回收与模型学习，**

   实现从“能用”到“敢用、常用”，从“给建议”到“能执行、会复盘”。其中，“许愿即投”依赖调价、诊断、数据、创编等子 Agent 能力成熟，以及编排中枢、Tool／Skill、记忆和链路级评测等底层能力就绪。

### 二、核心突破：可交互调价 Agent——先对内再对外

- **思路：把出价／调价的基础能力当作「基座」，让客户直接和它交互**——用自然语言"许愿"一个投放效果，替代复杂的创编交互和出价策略配置。调价 Agent 负责“看懂状态、算出方案、执行调整、复盘效果”，磁力小牛负责“听懂诉求、补齐约束、展示方案、完成协商和串联执行”。**客户只需说出投放目标，无需理解复杂的出价参数和策略配置**。
- **链路**：客户表达业务目标 → 小牛识别意图并补齐计划范围、预算上限和风险边界 → 调价 Agent 判断计划状态、定位瓶颈并计算调整方案 → 小牛展示调整依据、参数变化及预计影响 → 客户确认或授权 → 调价 Agent 执行并检查结果 → 小牛回访实际效果。
- **Agent 协同与 Memory 沉淀**：小牛通过“扩量”“控成本”“诊断计划状态”等粗粒度工具调用调价能力，并按需联动诊断、数据和创编 Agent；调整结果同时反馈给调价 Agent 和小牛记忆，沉淀客户的授权范围、调整偏好及否决理由，形成“客户目标 → 调整决策 → 协商执行 → 效果验证 → 持续学习”的闭环。
![[Pasted image 20260909143742.png]]
**这里最关键的设计是「可协商」，它和"白盒告知"有本质区别：**

| 做法 | 客户体验 | 归因权在谁 |
|---|---|---|
| 黑盒自动 | 半夜把出价从 3.2 降到 2.8，第二天才发现；唯一能做的是关掉这个功能 | 平台 |
| 白盒告知 | 降完发通知"因 ROI 低于目标已降价"——事已经做了，这是通知 | 平台 |
| 可协商 | 动手前给变更清单＋判断依据＋预估代价，客户可接受／改数值／先观察／追问为什么；下一轮带着上次结果回来 | 客户 |

> **为啥要这么做：** **阿里是货架电商，没有开播中的实时性压力；腾讯没有电商成交闭环，拿不到实时成交反馈（注意它已在做"专场放量／直播快推"，空档比预估窄）；千川同场景但已自陈卡在客户"不理解"。** 而白盒本身已被腾讯量产、降级为入场门票——**我们要赢的不是"有卡片"，而是"开播中 10 秒内能协商完、且下一轮带着上次结果回来"。**

|---|---|---|---|

**小牛怎么应用**

**链路 A｜诊断复用状态理解**

> 客户问"为什么不跑量" → 诊断 Agent 调调价Agent 查计划状态 → 拿到"处于冷启、出价竞争力不足、预算未受限"+依据 → 诊断 Agent 叠加自己的知识库（审核规则、行业基准）产出结论和建议 → 建议里的调价动作交回调价 Agent 执行
**链路 B｜创编agent与调价agent的协同**

> 创编生成方案 → 调用调价Agent 预判(配置, 目标) 拿到预估跑量／成本 → 预估值随方案一并展示给客户 → 客户确认后建计划，出价参数交由调价 Agent 接管持续调控 → 效果回收进飞轮
**链路 C｜可协商调价（白盒主场景）**

> 事件触发或客户开口 → 中枢路由到调价 Agent → 调价给出**变更清单＋依据＋预估代价** → 我们的沙箱做预演（改前 vs 改后）→ **客户逐条勾选** → 执行 → 结果进飞轮 → 记忆沉淀客户的否决理由
**小牛怎么接入**

协同定位：可交互调价 Agent 由调价团队建设，我们与之是**协同关系**。**我们需要的不是"改出价的接口"，而是"账户与计划的状态理解能力"。**

调价 Agent 为了决定加还是减，需先判断账户和计划此刻处于什么状态——**这项判断能力做好后，它天然具备对账户和计划的诊断能力，以及一定的预判和反思能力，可作为创编、诊断的共用基座**。

### 1.海外产品对我们的启发

#### 1.1 Tool 按客户会说的那句话封装,并做过滤机制

**Tool 是什么**:AI 要干活,得有"手"。每一个能执行的动作就是一个 Tool——查数据是一个、改出价是一个、提交审核是一个。AI 自己不会改出价,它只能"调用改出价这个工具"。

**"按客户会说的那句话封装"什么意思**:

看两种设计法。客户想干一件事:**"把这个计划的量提上去"**。

**千川式(按后端接口拆)**:

```plain text
工具1:查计划当前出价
工具2:改出价
工具3:查预算
工具4:改预算
工具5:查定向
工具6:改定向

```

AI 得自己想:先查什么、再改什么、改多少、哪一步失败了怎么办。**六个工具,AI 要自己编排,还容易漏或者顺序错。**

**Amazon 式(按客户那句话封装)**:

```plain text
工具:扩量(计划ID, 目标量级)
   └─ 内部自动:查现状 → 判断瓶颈是出价还是预算还是定向 → 算调整幅度 → 执行 → 校验

```

**一个工具,AI 只管调用,复杂逻辑封在里面。**

Amazon 那个真实例子最直观:`"Add UK to [campaign_id] with a £10 budget"`——**一句话背后是翻译文案、新建活动、按英国CPC重算出价、配英镑币种、检查商品在英国有没有上架,几十步。** 但对 AI 来说就是调一个工具。

**为什么千川补半年还"覆盖不足"**:因为按接口粒度补,**一个工具只覆盖一个按钮**。后台有500个按钮,你得补500个工具,补完 AI 还是不知道怎么组合。按客户那句话封装,**一个工具覆盖一整类需求**,20个工具可能就够用了。

**"过滤机制"是什么**:工具太多 AI 会变笨。因为所有工具的说明书都要塞进 AI 的上下文里,塞太多它就分不清该用哪个,而且费token。所以要能**按场景只加载需要的工具组**——客户在问数据,就只给它数据类工具,别把审核、创编那些也塞进去。Amazon 官方文档里专门写了这个机制,还说明了理由:**减少上下文token、提升回答质量。** 这是踩过坑才会写进文档的。

#### 1.2 Skill 层要有官方固化的最佳实践

**Tool 是"手",Skill 是"该怎么做事的说明书"。**

举个例子。客户说"我的计划成本太高了"。AI 有一堆工具可用,但**它该按什么顺序查?** 是先看素材衰退,还是先看竞争加剧,还是先看定向太窄?调整的时候该先动出价还是先动定向?降多少算合理?

如果不告诉它,**AI 会自己瞎猜一套流程,每次还不一样**——今天先查素材,明天先查定向,给客户的结论就不稳定。

**Skill 就是把老师傅的经验写成 AI 能读的提示词**:「诊断成本高,先按这个顺序排查:①素材CTR是否衰退 ②同行竞价是否上涨 ③定向是否过窄 ④转化率是否下滑;确认原因后按这个优先级调整...」

Amazon 官方把 Skill 定义成了 **MCP 的标准原语之一**,定义是「**Amazon Ads 提供的预定义提示词,引导 AI 应用走完整个广告工作流、并教它怎么用工具**」。它自己的话说这些东西 **"充当操作说明书"(instruction manual)**。

**它跟千川的区别在于:千川的 Skill 是自己写给自己的 Agent 用;Amazon 的 Skill 是写好了给全世界所有接入的 Agent 用。** 意思是它把"怎么投好广告"这件事的标准答案自己定义了。

别只做工具,得同时沉淀"**这类问题该怎么一步步解**"的固化流程。不然每个 Agent 各自摸索,效果不稳定,而且经验不能复用——**这正是千川"各方向都在能力建设中、落地见效慢"的原因之一。**

#### 1.3 Agent 站在托管之上

这条讲的是**定位问题:Agent 是取代自动投放,还是管理自动投放?**

已经有 UAX、智能出价、自动扩量这些托管能力,而且非电商域跑到了近80%渗透。**Agent 不该去重做一遍这些事。**

**错误做法**:做一个 Agent,让它自己去算出价、自己选人群

**Amazon 的做法**:Ads Agent 干的是**上一层的事**——

- 帮你搭活动结构(建几个活动、怎么分组)
- 建议投哪些人群(从几千个人群里筛)
- 跨几百个计划调节奏和预算分配
- 写 AMC 的 SQL 查询帮你分析

**具体的出价优化,还是交给底下的自动出价系统**。有个细节特别能说明这个层级关系:**Ads Agent 甚至会建议你"把自动活动里跑得好的词挪到手动活动去"**——它在**指挥托管系统怎么用**,而不是替代它。

投放总Agent 的定位应该是**编排和管理已有的托管能力**,不是再造一套自动投放。这样立项也好讲——不是推翻现有能力,是把它们串起来、让客户能指挥它们。

#### 1.4 白盒(先给变更清单→客户勾选→才执行)是核心原则不是可选项

这条是最重要的一条,因为它直接对着千川——**「智能可调价显示『不理解』是首要主因」**。

**问题在哪**:系统自动调价,客户看不见过程。效果好了他觉得是自己运气,效果差了他确定是平台坑他。**因为他只能用结果反推动机。** 在信息不对称的情况下,客户默认平台是自利的——**这在他的位置上完全理性。**

**Amazon 的解法不是"解释完就自己动手",是"解释完等你点头"。** 官方 FAQ 原文:

> **「Ads Agent 在执行任何改动前,会先汇总所有建议的变更内容,让您自主决定采纳哪些修改。在您审查并批准相关改动后,Ads Agent 才会进行您所指定的更改。」**

产品页上那个卖点标题写的是:**「保持透明度,掌控全局」**。

拆成三步就是:

| 步骤 | 具体做什么 |
|---|---|
| 1. 给变更清单 | 不是"我帮你优化好了",而是"我打算做这5件事:计划A出价从3.2降到2.8、计划B预算加500..." |
| 2. 客户勾选 | 每一条都能单独选择要不要。客户可以只批准3条、否掉2条 |
| 3. 才执行 | 客户点头之后才动手,只做他批准的那些 |

**为什么这是"核心原则"而不是"可选功能"**:

因为**顺序反了效果完全不同**。如果先执行再解释,客户的体验是"你已经动了我的账户,现在跟我解释"——**那是通知,不是协商。** 先给清单再执行,客户的体验是"我做的决定,系统给我建议"——**归因权在他手上。**

而且这个设计**顺手解决了三个问题**:

1. **信任**:客户知道系统要干什么,才敢开
2. **合规**:每次变更有客户明确授权,可追溯(Amazon 那个 AI Agent 政策就要求"人工授权检查点")
3. **教育**:客户看多了变更清单,慢慢就懂了系统的逻辑,**信任建立起来之后才会愿意放手**

**这就是"白盒不是为了提升效果,是为了把归因权还给客户"的意思。** 客户敢把预算和控制权交出来,平台才真正拿到自动化的收益。**千川卡住的地方不是模型不行,是客户不肯放手。**

**四条串起来看是一条逻辑链:**

**工具要按客户的话来封装(能干活)→ 要有固化的最佳实践指导怎么用(干得稳)→ Agent 管理托管而不是取代它(不重复造轮子)→ 每次动手前先给清单等客户点头(客户敢用)。**

前三条决定它能不能干活,第四条决定客户会不会用。**千川前三条在补,第四条没解决,所以有能力但没人敢用。**

### 2.千川咋干的

#### 2.1 一句话看懂千川的AI布局

千川不是在做"几个AI功能"，而是在搭**一套完整的AI产品工厂**：底下是Agent基建（架构+工具+评测+训练），中间是四条业务线（自助服务、营销、AIGC创意、增长），上面用"电商One Agent"统一对客。**他们的思路是先把生产AI能力的流水线建好，再批量出场景。**

|  | 千川在建什么 | 进度 |
|---|---|---|
| ① 统一对客入口 | 电商One Agent：把「私域AI小二」和「商家AI助手」整合成一套Agent架构、一套对外心智 | Q3规划中 |
| ② 业务Agent | 商家claw（任务托管）、营销Agent（活动+工具+答疑+诊断）、创意Agent（AIGC白盒）、增长Agent | 部分灰测，效果参差 |
| ③ Agent基建 | 基建管理平台（提示词+技能配置）、agentloop架构、skill在线创编、评测回放调试、MCP工具封装 | 一期上线，二期推进中 |
| ④ 评测与训练 | 电商统一benchmark（含广告+经营）、三层评测框架、AI训练师、CSM人机协同训练 | Q2跑通模式，Q3扩范围 |

#### 2.2 四条业务线在干什么

**① 自助服务：把抖店和千川的AI助手合成一个**

千川Q2启动了「千川×电商自助产品体系融合」，定位是「**被动服务 + 主动运营 + 代操作托管**」一体化，覆盖「经营+广告」全场景。具体在做四件事：

| 项目 | 做什么 | 状态 |
|---|---|---|
| BPO/CSM工作台 | 客服/服务商工作台切换 | 5月已上线 |
| 商家AI助手 | 统一抖店与千川AI助手的前端SDK，统一全场景能力和对客表达 | 7月中上线 |
| 私域AI小二 | 统一电商与广告的企微租户、迁移好友关系、统一策略配置，实现多Agent协同分流 | 7月底上线 |
| 商家claw | Agent架构+模型升级，具备自主规划、多轮推理、工具调用；新商场景试点"一键完成任务" | 目标8月内上线正式版 |

**claw的真实状态值得注意**：架构和模型已升级到具备自主规划能力，新商场景试点也拿到了任务完成率和冷启成功率的收益。但内部明确写了两个问题——**「工具覆盖和质量不足，目前可用场景较少」**、**「功能分散多个入口，动线不清晰」**。

> 对我们的启示：Agent的瓶颈不在模型能力，在**工具覆盖度和入口收敛**。我们小牛已接入7个Agent，要提前避免"能力有了但客户找不到"的问题。

**② 营销Agent：跑通了两类Skill，但效果不及预期**

千川营销Agent的建设路径很值得抄：**先做对客理解 → 建知识资产 → 建评测机制 → 再写Skill**。

| 环节 | 具体做法 |
|---|---|
| 对客理解 | 梳理「商家客诉进线、抖店AI助手、小二企微」全渠道商家原声 14.5万条，用trae&aime交叉打标，按"大促/日常活动 × 价格类/非价格类"四大场景拆解问题分类 |
| 知识资产 | 统一交付面向各方向AI产品的营销知识库，沉淀营销知识及工具能力 |
| 评测机制 | 以结果/过程/体验/风险为主框，结合商家Journey拆解评测标准，基于真实query输出评测集，跑通初轮测评并明确归因迭代方案 |
| Skill落地 | 已跑通两类执行Skill：活动管理（查询/报名/修改/议价/退出）、商家营销工具（单品直降/商家优惠券/新人礼金创建），已启动灰测 |

**但结果是**：Q2跑通的两类Skill「**整体初期效果不及预期，待1.0版本优化**」；规划的三类Skill（答疑/执行/分析诊断）「**Q2仅完成优先级与范围盘点，未对齐最终方案，节奏偏慢**」。

Q3他们的解法是两个闭环机制：

- Skill生产闭环：**问题分类 → query抽取 → 预期行为编写 → Skill能力推导 → 评测**
- 评测框架：**安全断言 → 硬质量断言 → 软质量打分**

   三层，跑通Skill隔离评测 + 端到端评测

> 对我们的启示：这套「原声打标→知识库→评测集→Skill」的顺序值得直接复用。**注意他们是"评测机制先建好，再写Skill"**——我们小牛的评测平台一期正好在做，节奏对得上。三层评测框架（安全/硬质量/软质量）可以直接借。

#### 2.3 AIGC：唯一大规模见效的方向

这是千川Q2最亮的一块，也是唯一目标大幅超额的：

| 指标 | Q1末 | Q2末 | 环比 | 目标达成率 |
|---|---|---|---|---|
| 动态创意总消耗 | 6，763万 | 14，235万 | +110.5% | 142% |
| 动态创意总渗透 | 5.16% | 9.77% | +89.5% | — |
| 直播AIGC消耗占直播R2大盘 | 7.15% | 12.75% | +78.3% | 131% |
| 直播屏蔽AIGC反转实验 | 1.77% | 3.55% | +100.7% | 157% |
| 商品AIGC消耗占商品R2大盘 | 2.56% | 6.10% | +138.0% | 125% |
| 直播动态创意开启计划消耗渗透 | 10.10% | 16.71% | +65.3% | 128% |

**怎么做到的**：

- 直播个性化quote + 潜力素材出价策略 → 素材ARPU **23.7→38.45**

   （116%超自提）
- 商品新素材必建 → 在投素材金 **258万→815万**
- 高跑量素材披露 + 618大促GTM → 直播渗透 **+24pp**

   （43.42%→67.5%）
- 货架图文（商品卡+视频封面）行业手法策略 → 千川搜索advv **+1.2%**

**白盒化是他们的明确方向**：为支持生成策略激进探索、满足商家个性化需求，推进**成片推荐 + 创意Agent**，目标是让创意生产**「可交互 - 可反馈 - 可迭代」**，6月底/7月上线灰度。

**新生成策略在攻短剧**：短剧AIGC把中插广告从"剧情外硬插"升级为"剧情内原生供给"，全AIGC剧情类badcase率降至60%、口播类33%；通用剧情类「无商品版剧情前贴+自提分镜」badcase率 对我们的启示：**「可交互-可反馈-可迭代」正是我们调价Agent的同一套逻辑，千川已在创意侧验证了这个方向。**另外他们用badcase率做AIGC质量的量化指标，这个度量方式比"满意度"更可落地。

#### 2.4 增长：从"点子驱动"转向"Agentic驱动"

| 方向 | 做法与结果 |
|---|---|
| 广告客增 | 复盘历史方法论局限，明确「点子驱动 → Agentic驱动」的增长路径并完成收益验证；大盘店铺投广率46.8%（QoQ+2.7pp，YoY+5.1pp），目标完成率103.8% |
| 商家增长 | 线索生产、内广、外呼渠道的AI能力升级，开始引入反思机制让模型自迭代；产品化触达对入驻的贡献 30.3%→33.9% |
| 自助运营 | 618大促与双高品报名不投入人工任务，靠个性化问询+多轮会话提升客户开口；开口率8.9% vs 人工任务2.5%，其中个性化问询12.5% |

> 对我们的启示：自助运营那条数据很硬——**AI主动问询的客户开口率是人工任务的3.6倍**。这对我们「主动触达」方向是强支撑。
